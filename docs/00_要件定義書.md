## 1. 概要

自分のレシピを登録・検索・整理できるWebアプリを、スクール初級編の最終課題として作成する。

### 1.1 目的

- 手書きメモやブックマークに散らばったレシピを1か所にまとめる
- 材料や料理名からすぐに目的のレシピを探せるようにする
- 課題として、CRUD・ログイン・検索といったWebアプリの基本機能を一通り実装する

### 1.2 対象ユーザー

| ユーザー | 説明 |
| --- | --- |
| 一般ユーザー | 自炊をする個人。会員登録してレシピを管理する |
| ゲスト | 未ログインの訪問者。公開レシピの閲覧のみ可能 |

### 1.3 スコープ

- 対象内: レシピの登録・編集・削除・閲覧、検索、カテゴリ分け、お気に入り、ユーザー認証
- 対象外: 決済、SNS連携、スマホネイティブアプリ、栄養価の自動計算

### 2.1 機能要件（要点）

- 必須10機能（F-01〜F-10）と任意4機能（F-11〜F-14）の計14機能。
- 必須: ユーザー登録、ログイン、レシピの一覧・詳細・登録・編集・削除、カテゴリ分け、キーワード検索、入力チェック。
- 編集・削除は投稿者本人のみ。ゲストは閲覧と検索だけできる。

→ 詳細は [機能一覧](01_機能一覧.md)

### 2.2 画面（要点）

- 必須6画面＋任意1画面。トップ（レシピ一覧・検索）を起点にする。
- レシピの登録・編集にはログインが必要。

→ 詳細は [画面仕様書](02_画面仕様書.md)

### 2.3 データ（要点）

- users・recipes・ingredients・steps・categories・favorites の6テーブル。
- 1人のユーザーが複数のレシピを持ち、1つのレシピが複数の材料と手順を持つ。

→ 詳細は [データベース設計書](03_データベース設計書.md)

### 2.4 非機能要件（要点）

- パスワードはハッシュ化して保存し、他人のレシピは編集・削除できないようにする。
- PC の Chrome を基本に、スマートフォン幅（375px）でも崩れないようにする。

→ 詳細は [非機能要件](04_非機能要件.md)

### 2.5 技術構成（要点）

- フロントエンド Next.js + TypeScript、バックエンド Rails（API モード）、データベース MySQL。
- 本番環境は Amazon EC2 + Amazon RDS for MySQL。

→ 詳細は [技術スタック](05_技術スタック.md)

## 3. スケジュール

3週目末までに必須機能を完成させ、4週目は仕上げに使う。4週間を想定しているので、提出期限が決まったら週を割り当て直す。

| 週 | テーマ | 作業 |
| --- | --- | --- |
| 第1週 | 設計 | 要件定義書の確定、画面設計・DB設計、環境構築・Git準備 |
| 第2週 | 基本機能 | ユーザー登録・ログイン、レシピ登録・一覧・詳細、編集・削除・権限 |
| 第3週 | 検索と品質 | カテゴリ・検索、入力チェック、必須機能の動作確認 |
| ◆ 3週目末 | **区切り** | **必須機能（F-01〜F-10）が完成していること**。遅れていたら任意機能は見送る |
| 第4週 | 仕上げ | 任意機能（余裕があれば）、テスト・不具合修正、デプロイ・提出準備 |
