# レシピ管理アプリ 要件定義書

作成日: 2026-11-05（技術構成を 2026-11-06 に更新）

## 1. 概要

自分のレシピを登録・検索・整理できるWebアプリを、スクール初級編の最終課題として作成する。

### 1.1 目的

- 手書きメモやブックマークに散らばったレシピを1か所にまとめる
- 材料や料理名からすぐに目的のレシピを探せるようにする
- 課題として、CRUD・ログイン・検索といったWebアプリの基本機能を一通り実装する

### 1.2 対象ユーザー

| ユーザー | 説明 |
| --- | --- |
| 一般ユーザー | 自炊をする個人。会員登録してレシピを管理する |
| ゲスト | 未ログインの訪問者。公開レシピの閲覧のみ可能 |

### 1.3 スコープ

- 対象内: レシピの登録・編集・削除・閲覧、検索、カテゴリ分け、お気に入り、ユーザー認証
- 対象外: 決済、SNS連携、スマホネイティブアプリ、栄養価の自動計算

## 2. 機能要件

優先度「必須」の10機能を提出までに完成させ、「任意」は時間に余裕があれば実装する。

| No | 機能 | 内容 | 優先度 |
| --- | --- | --- | --- |
| F-01 | ユーザー登録 | 名前・メールアドレス・パスワードで新規登録する | 必須 |
| F-02 | ログイン／ログアウト | メールアドレスとパスワードで認証する | 必須 |
| F-03 | レシピ一覧 | レシピを新しい順にカード形式で表示する（1ページ 12件） | 必須 |
| F-04 | レシピ詳細 | 料理名・画像・材料と分量・手順・調理時間・何人分を表示する | 必須 |
| F-05 | レシピ登録 | 上記の項目を入力して保存する。材料・手順は行を追加できる | 必須 |
| F-06 | レシピ編集 | 自分が登録したレシピのみ編集できる | 必須 |
| F-07 | レシピ削除 | 確認ダイアログの後、自分のレシピを削除する | 必須 |
| F-08 | カテゴリ分け | 主菜・副菜・汁物・デザートなどから1つ選んで設定する | 必須 |
| F-09 | キーワード検索 | 料理名・材料名の部分一致で検索し、カテゴリで絞り込む | 必須 |
| F-10 | 入力チェック | 必須項目の未入力や文字数超過時にエラーメッセージを表示する | 必須 |
| F-11 | お気に入り | レシピをお気に入り登録・解除し、一覧で確認する | 任意 |
| F-12 | 画像アップロード | 完成写真を1枚添付する（未設定時はダミー画像） | 任意 |
| F-13 | 公開／非公開 | レシピごとにゲストへの公開を切り替える | 任意 |
| F-14 | マイページ | 自分のレシピとお気に入りをまとめて表示する | 任意 |

### 2.1 権限

| 操作 | ゲスト | ログインユーザー | 投稿者本人 |
| --- | --- | --- | --- |
| 公開レシピの閲覧・検索 | ○ | ○ | ○ |
| レシピ登録 | × | ○ | ○ |
| お気に入り | × | ○ | ○ |
| 編集・削除 | × | × | ○ |

## 3. 画面一覧と画面遷移

必須画面は6つで、トップ（レシピ一覧・検索）を起点にする。

| ID | 画面名 | URL（例） | ログイン | 対応機能 |
| --- | --- | --- | --- | --- |
| S-01 | レシピ一覧・検索（トップ） | / | 不要 | F-03, F-08, F-09 |
| S-02 | レシピ詳細 | /recipes/:id | 不要 | F-04, F-07, F-11 |
| S-03 | レシピ登録 | /recipes/new | 必要 | F-05, F-10, F-12 |
| S-04 | レシピ編集 | /recipes/:id/edit | 必要（本人） | F-06, F-10 |
| S-05 | ユーザー登録 | /signup | 不要 | F-01 |
| S-06 | ログイン | /login | 不要 | F-02 |
| S-07 | マイページ（任意） | /mypage | 必要 | F-14 |

### 画面遷移

ゲストは一覧と詳細まで、登録・編集にはログインが必要。

| 遷移元 | 操作・条件 | 遷移先 |
| --- | --- | --- |
| ログイン | 認証成功 | レシピ一覧・検索 |
| ログイン ⇄ ユーザー登録 | 画面内のリンク | ユーザー登録 ⇄ ログイン |
| ユーザー登録 | 登録完了 | レシピ一覧・検索 |
| レシピ一覧・検索 | カードを選択 | レシピ詳細 |
| レシピ一覧・検索 | 要ログイン | レシピ登録 |
| レシピ登録 | 保存 | レシピ詳細 |
| レシピ詳細 ⇄ レシピ編集 | 本人のみ（保存で詳細に戻る） | レシピ編集 ⇄ レシピ詳細 |
| レシピ詳細 | 削除 | レシピ一覧・検索 |

共通ヘッダーからはどの画面でも一覧・レシピ登録・ログインに移動できる。詳細画面で削除すると一覧に戻る。

## 4. データ設計

テーブルは6つ（favoritesはF-11実装時のみ）。ユーザー1人が複数のレシピを持ち、1つのレシピが複数の材料と手順を持つ。

### users（ユーザー）

| カラム | 型 | 制約 |
| --- | --- | --- |
| id | integer | 主キー |
| name | string | 必須、20文字以内 |
| email | string | 必須、一意 |
| password_digest | string | 必須（ハッシュ化して保存） |
| created_at / updated_at | datetime | |

### recipes（レシピ）

| カラム | 型 | 制約 |
| --- | --- | --- |
| id | integer | 主キー |
| user_id | integer | 外部キー（users） |
| category_id | integer | 外部キー（categories） |
| title | string | 必須、50文字以内 |
| description | text | 200文字以内 |
| cooking_time | integer | 分、1〜999 |
| servings | integer | 人分、1〜20 |
| image | string | 画像のパス（任意） |
| is_public | boolean | 初期値 true |
| created_at / updated_at | datetime | |

### ingredients（材料）

| カラム | 型 | 制約 |
| --- | --- | --- |
| id | integer | 主キー |
| recipe_id | integer | 外部キー（recipes）、レシピ削除時に合わせて削除 |
| name | string | 必須（例: 玉ねぎ） |
| quantity | string | 例: 1個、大さじ1 |

### steps（手順）

| カラム | 型 | 制約 |
| --- | --- | --- |
| id | integer | 主キー |
| recipe_id | integer | 外部キー（recipes）、レシピ削除時に合わせて削除 |
| position | integer | 手順番号 |
| body | text | 必須 |

### categories / favorites

| テーブル | カラム | 備考 |
| --- | --- | --- |
| categories | id, name | 初期データとして登録（主菜・副菜・汁物・ご飯もの・デザート・その他） |
| favorites | id, user_id, recipe_id | user_id と recipe_id の組み合わせは一意（F-11を実装する場合） |

## 5. 非機能要件

初級課題の範囲で、安全に・迷わず使えることを優先する。

| 区分 | 要件 |
| --- | --- |
| 性能 | 一覧・詳細ページは通常の回線で3秒以内に表示する |
| セキュリティ | パスワードはハッシュ化して保存する。他人のレシピの編集・削除URLに直接アクセスしても実行できない |
| セキュリティ | 入力値はエスケープして表示し、XSSを防ぐ。フォームにCSRF対策を入れる |
| ユーザビリティ | 全ページ共通のヘッダーからトップ・登録・ログインに移動できる。処理後に完了メッセージを表示する |
| 対応環境 | PCのChrome最新版を基本とし、スマートフォン幅（375px）でもレイアウトが崩れない |
| 画像 | アップロードは jpg / png、1枚 5MB まで |
| 保守性 | Gitでバージョン管理し、機能ごとにコミットする。READMEに起動手順を書く |

## 6. 技術構成・スケジュール・今後の拡張

### 6.1 技術構成

フロントエンド（Next.js）とバックエンド（Rails API）を分け、JSONでやり取りする。

| 層 | 使用技術 |
| --- | --- |
| フロントエンド | Next.js（App Router）+ TypeScript |
| バックエンド | Ruby on Rails（APIモード） |
| データベース | MySQL 8（開発は Docker、本番は Amazon RDS） |
| 認証 | has_secure_password + トークン認証 |
| バージョン管理 | Git / GitHub |
| デプロイ | Amazon EC2（Next.js と Rails）+ Amazon RDS for MySQL |

### 6.2 スケジュール

3週目末までに必須機能を完成させ、4週目は仕上げに使う。4週間を想定しているので、提出期限が決まったら週を割り当て直す。

| 週 | テーマ | 作業 |
| --- | --- | --- |
| 第1週 | 設計 | 要件定義書の確定、画面設計・DB設計、環境構築・Git準備 |
| 第2週 | 基本機能 | ユーザー登録・ログイン、レシピ登録・一覧・詳細、編集・削除・権限 |
| 第3週 | 検索と品質 | カテゴリ・検索、入力チェック、必須機能の動作確認 |
| ◆ 3週目末 | **区切り** | **必須機能（F-01〜F-10）が完成していること**。遅れていたら任意機能は見送る |
| 第4週 | 仕上げ | 任意機能（余裕があれば）、テスト・不具合修正、デプロイ・提出準備 |

必須機能を3週目までに完成させ、最終週を予備にしておけば、任意機能が間に合わなくても提出できる。
