# レシピ帳 機能要件まとめ

作成日: 2026-11-06

必須の10機能（F-01〜F-10）のうち、実装済みは3つ、一部実装は3つ、未着手は4つ。「一部実装」は、ログイン機能がないために本人チェックができないものと、ページ分けがない一覧。

## 2. 入力項目とチェックのルール

必須は料理名だけで、材料と手順は0件でも保存できる。チェックは API（Rails）で必ず行い、画面でも一部を先に止める。

| 項目 | 必須 | ルール | 画面での制限 |
| --- | --- | --- | --- |
| 料理名 | 必須 | 50文字以内 | 空欄では送信不可、51文字目は入力不可 |
| ひとこと説明 | 任意 | 200文字以内 | 201文字目は入力不可 |
| 調理時間（分） | 任意 | 整数 1〜999 | 数値入力欄、範囲外は送信不可 |
| 何人分 | 任意 | 整数 1〜20 | 数値入力欄、範囲外は送信不可 |
| 材料名 | 材料行を入れるなら必須 | 50文字以内 | 材料名が空の行は保存時に捨てる |
| 分量 | 任意 | 30文字以内（例: 1個、大さじ1） | なし（API でチェック） |
| 手順の内容 | 手順行を入れるなら必須 | 500文字以内 | 空の行は保存時に捨てる |
| 手順番号 | 自動 | 並び順から 1, 2, 3… と振り直す | 入力欄なし |

チェックに引っかかると、フォームの上に「料理名を入力してください」のような日本語のメッセージが出て、入力内容は残る。

## 3. 画面ごとの動き

画面は4つで、どの画面でもヘッダーから「一覧」と「レシピを登録」に移動できる。

| 画面 | URL | できること | 操作後の移動先 |
| --- | --- | --- | --- |
| S-01 レシピ一覧 | / | 全レシピを新しい順にカード表示（料理名・説明・調理時間・何人分）。0件なら登録への案内を表示 | カードを押すと S-02 |
| S-02 レシピ詳細 | /recipes/:id | 材料と分量、番号つきの手順を表示。「編集する」「削除する」ボタン | 編集 → S-04、削除 → 確認のあと S-01 |
| S-03 レシピ登録 | /recipes/new | 入力フォーム。「＋ 材料を追加」「＋ 手順を追加」で行を増やし、各行の「削除」で消せる | 保存成功 → 登録したレシピの S-02 |
| S-04 レシピ編集 | /recipes/:id/edit | S-03 と同じフォームに今の内容が入った状態で開く | 保存成功 → S-02 |

- 編集で保存すると、材料と手順はフォームの内容でまるごと入れ替わる。入力エラーのときは何も変わらない。
- レシピを削除すると、その材料と手順も一緒に消える。
- 存在しない ID を開くと「レシピが見つかりませんでした。」、API が止まっていると「レシピを読み込めませんでした。…」と表示する。

## 4. 要件定義書との差分と確認リスト

### 4.1 要件定義書と違うところ

- ログインがないため、誰でも全レシピを編集・削除できる（権限表は未反映）。
- recipes テーブルに user_id・category_id・image・is_public はまだない。対応する機能を作るときに追加する。
- 材料名50文字・分量30文字・手順500文字の上限は実装時に決めた値で、要件定義書にはまだ書いていない。

### 4.2 ブラウザでの確認リスト

http://localhost:3000 で、上から順に試す。

- [ ] 一覧に「親子丼」のカードが表示される
- [ ] カードを押すと、材料（2件）と手順（2つ）が詳細に表示される
- [ ] 「レシピを登録」で料理名を空のまま送ると、送信できない
- [ ] 材料・手順を行追加して登録すると、詳細画面に移動して内容が合っている
- [ ] 手順の途中の行を削除すると、番号が 1, 2, 3… に振り直される
- [ ] 編集画面に今の内容が入っていて、更新すると詳細に反映される
- [ ] 削除で確認ダイアログが出て、OK で一覧から消える
- [ ] スマホ幅（開発者ツールで 375px）でもレイアウトが崩れない
